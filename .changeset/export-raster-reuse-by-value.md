A browser export no longer wraps the page's CSSOM to tell that a frame holds still or that a box away from the viewport can be written as before. The still check and the far-box cache now compare the text of every rule in the style sheets that apply (a font face without its source), focus (`:focus-visible` included) and what each Web Animation shows (its target, composite modes, iteration progress and keyframes, a CSS animation's through the text of its rule) by value, besides the DOM mutations, loads, popover toggles and font loads they observe. An edit the wrappers missed, such as a rule declaration the parent page took from the live page before the export and later set by property name, no longer leaves a stale frame, nor does a CSS image that sizes a box (`content`, `list-style-image`, `shape-outside`) finishing its load after the frame read that box, also a box away from the viewport that the image grows into view, a popover opened in the same task as the frame, an element that starts to show its focus, or what the engine updates only at its next rendering update after a scroll or a layout change (scroll-state container queries, anchor positions and their fallbacks): the first frame after a change walks once more after that update. The live page is not read while it waits out of view before going live, and its font faces are no longer drawn into the frames then (the page's text could not use them). Reading the rules back costs about 3 µs a rule in Chromium: at 1280x720 a still frame of `examples/markdown/welcome.zh.md` or `examples/web/demo.html` takes about 1.7 ms instead of 0.8 ms and the export about 1 to 2% longer, with the same frames; on a page with 5,000 rules a still frame takes about 18 ms instead of 1 ms and the export about 10% longer. A page that fades in 200 cards with CSS animations exports as fast as before.
