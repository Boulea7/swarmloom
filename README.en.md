An adapter or DOM snapshot turns the input into a shared Blueprint, and the player choreographs cursors in reading order. Studio plays live; the CLI exports frame by frame on a virtual clock.

## Quick start

### No installation: Studio

Open [Studio online](https://boulea7.github.io/swarmloom/studio/) and choose an example, drop a local file, paste text or enter a URL. Local files are processed in the browser. A remote URL is requested directly by your browser and remains subject to CORS and access permissions.

### CLI

The CLI already runs from source. After completing the source build below, run this from the repository root:

```bash
node apps/cli/dist/cli.js render examples/svg/emblem.svg -o emblem.mp4 --seed 7 --fps 30
```

It needs Node.js 20+ and Chrome/Chromium; MP4, WebM, GIF and WebP also need FFmpeg 4+. Run `node apps/cli/dist/cli.js doctor` to check your environment. `npx swarmloom@latest ...` is the planned entry point once the npm package is published; it is not available yet.

### Web Component

`pnpm add @swarmloom/element` is the planned npm installation; for now, `pnpm --filter @swarmloom/element build` builds it from source. The component interface is implemented:

```html
<script type="module">
  import { define } from "@swarmloom/element";
  define();
</script>

<swarm-loom
  src="./demo.md"
  type="markdown"
  agents="24"
  seed="7"
  theme="auto"
  labels="names"
  autoplay
  controls>
</swarm-loom>
```

See the [component guide](https://boulea7.github.io/swarmloom/docs/en/element.html) for all attributes, events and SSR notes.

## Install by platform

Store listings and signed packages have not been published. Current extensions are development packages built from source. The repository needs Node.js 22.12+ and uses the pnpm version pinned in `packageManager`.

```bash
git clone https://github.com/Boulea7/swarmloom.git
cd swarmloom
corepack enable
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 pnpm install
pnpm build
pnpm --filter @swarmloom/extension build
```

<details>
<summary>Chrome / Edge / Brave / Opera: load a development package</summary>

- Chrome: `chrome://extensions` → Developer mode → Load unpacked → `apps/extension/dist/chrome/`.
- Edge: `edge://extensions`, then choose `apps/extension/dist/edge/`.
- Brave / Opera: enable Developer mode on their extension page and reuse `dist/chrome/`.
- Select the toolbar icon or press Alt+Shift+W on a normal page. Browser-internal pages, web stores and built-in PDF viewers cannot be injected.

</details>

<details>
<summary>Firefox desktop and Android: temporary debugging; signed release planned</summary>

On desktop, open `about:debugging#/runtime/this-firefox` → Load Temporary Add-on → `apps/extension/dist/firefox/manifest.json`; restarting Firefox removes it. Android uses the same package and needs web-ext, ADB and a debuggable device for development. Permanent installation requires an AMO-signed package. Until mobile hardware validation is complete, use Studio PWA.

</details>

<details>
<summary>Safari macOS / iOS / iPadOS / visionOS: source build; hardware and signing planned</summary>

On macOS with Xcode, run `pnpm --filter @swarmloom/extension package:safari`. Open `apps/extension/build/safari/` in Xcode, select a team, sign and run the container app, then enable the extension in system settings. Device distribution requires the Apple Developer Program; hardware acceptance on these platforms is not complete.

</details>

<details>
<summary>PWA: desktop, Android, iOS / iPadOS</summary>

In Chrome / Edge, open Studio and use “Install app” in the address bar or menu. On macOS Safari use “Add to Dock”; on Android use “Install app” or “Add to Home screen”; on iOS / iPadOS choose “Add to Home Screen” from Safari's Share menu. On Firefox desktop, use a normal tab.

</details>

<details>
<summary>Foldables and watches: honest boundaries</summary>

Foldables need no separate package: supported Viewport Segments enable dual-pane or stacked layouts, with a responsive fallback everywhere else. Watches have no extension and no promise of a full PWA. Open `?watch=1` for the muted small player or `?round=1` for a round-safe layout; generate and export complex scenes on another device.

</details>

## FAQ

1. **Is this an AI agent orchestrator?** No. The cursors are deterministic local animation replaying a visual build; they do not operate agents, and the rebuild does not execute scripts embedded in documents or HTML input.
2. **Are local files uploaded?** Never to a SwarmLoom server. Your browser contacts a remote site only when you open its URL; network images and fonts referenced by HTML can be disabled in Studio. See [Privacy](./PRIVACY.md).
3. **Why cannot every page be rebuilt in place?** Browsers block injection into internal pages, web stores and built-in PDF viewers. Import the file in Studio instead, or use the extension on a normal page that needs its signed-in state.
4. **Does the same seed guarantee a byte-identical MP4?** No. Identical input, browser, fonts, OS and settings can reproduce raw frames and PCM; encoder versions and threading may still change compressed bytes.
5. **Can phones and watches install the extension?** Phones use Studio PWA; a signed Firefox Android extension is still planned and being validated. Watches provide only the small player, with no extension or background playback.
