From the journal

Why we still count picks by hand

The loom is patient. It only asks that you know where the next thread goes.

Every cloth is a record of decisions. Each pass of the shuttle, or pick, lays one weft thread across the warp, and the pattern is nothing more than the order in which warp threads are lifted. Software can draw a drawdown in milliseconds, but counting picks by hand keeps the rhythm of the work in your fingers.

We built Loomworks around that rhythm. The planner shows the lift plan as a grid you can edit with the keyboard: arrows move, space toggles a cell, and shift extends a selection across a repeat. Nothing is hidden behind a modal, and every change can be undone.

Colour is the second half of the story. A palette is only useful if the threads actually exist, so each swatch links to a dye recipe with weights, temperatures and the lot number of the yarn. When two colours sit side by side in the weave, the mixer warns you if their contrast falls below what most eyes can tell apart.

A good draft reads like sheet music: you can hear the pattern before you weave it.

Finally, sharing should feel like handing a friend a folded sample. Links open a read-only view with the drawdown, the threading and the treadling side by side. If they like it, they can fork the pattern and start their own variation without touching yours.

This page is a test bed as well as a showcase. It mixes floats, grids, flex rows, sticky headers and an app-shell scroller so that every snapshot rule has something to bite on, from pseudo-element badges to the shadow root of a custom element further down.
