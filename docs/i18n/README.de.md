<h1 align="center">SwarmLoom</h1>

<p align="center"><strong>Sieh zu, wie ein Cursorschwarm es Stück für Stück zusammenwebt.</strong><br/>Ein Cursorschwarm baut Webseiten, Dokumente, Code, Bilder und 3D-Modelle vor deinen Augen Stück für Stück auf und exportiert das Ergebnis als Video mit Ton.<br/>Das ist eine lokale visuelle Wiedergabe, kein Orchestrator für KI-Agenten.</p>

## So funktioniert es

<p align="center">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="../../docs/assets/how-it-works-dark.svg" />
    <img alt="Webseite oder Datei lesen, Cursor in Lesereihenfolge anordnen und dann live abspielen oder als Video exportieren" src="../../docs/assets/how-it-works-light.svg" width="760" />
  </picture>
</p>

SwarmLoom zerlegt eine Webseite oder Datei in Ebenen und weist sie den Cursorn in Lesereihenfolge zu. Studio spielt den Aufbau live ab. Die CLI nimmt ihn Bild für Bild auf und fügt den Ton hinzu, sodass der Export nicht von der Geschwindigkeit deines Rechners abhängt.

## Schnellstart

### Online ausprobieren

Öffne [Studio online](https://boulea7.github.io/swarmloom/studio/) und wähle ein Beispiel, ziehe eine lokale Datei hinein, füge Text ein oder gib eine URL ein. Lokale Dateien bleiben in deinem Browser. Bei einer URL fragt dein Browser die jeweilige Website direkt an; diese muss lesende Cross-Origin-Zugriffe erlauben.

### Aus dem Quellcode bauen

GitHub Releases, npm-Pakete und Store-Einträge sind geplant. Bis dahin baust du SwarmLoom aus dem Quellcode. Du benötigst Node.js 22.12+; die pnpm-Version ist in `packageManager` festgelegt.

```bash
git clone https://github.com/Boulea7/swarmloom.git
cd swarmloom
corepack enable
pnpm install
pnpm build
```

### CLI

Aus dem Stammverzeichnis des Repositorys heraus kannst du eine Datei in ein Video umwandeln:

```bash
node apps/cli/dist/cli.js render examples/svg/emblem.svg -o emblem.mp4
```

Du benötigst Chrome oder Chromium; für MP4, WebM, GIF und WebP außerdem FFmpeg 4+. Prüfe deine Einrichtung mit `node apps/cli/dist/cli.js doctor`. Sobald das npm-Paket veröffentlicht ist, funktioniert `npx swarmloom` direkt (geplant).

Nützliche Optionen für Videoaufnahmen: `--opening 1.5` zeigt zuerst den Originalinhalt, `--intro outline` zeichnet zuerst die großen Konturen, `--overlays minimal` blendet Größenangaben und Hilfslinien aus, `--cue 12b:live` legt den Zeitpunkt des Live-Wechsels fest und `--beat-sync all` bringt Tastengeräusche auf den Beat. Alle Optionen stehen in der [CLI-Dokumentation](https://boulea7.github.io/swarmloom/docs/en/cli.html).

### Web Component

Das npm-Paket `@swarmloom/element` ist noch nicht veröffentlicht (geplant). Das Element selbst funktioniert bereits:

```html
<script type="module">
  import { define } from "@swarmloom/element";
  define();
</script>

<swarm-loom
  src="./demo.md"
  type="markdown"
  agents="24"
  seed="7"
  autoplay
  controls>
</swarm-loom>
```

Alle Attribute und Ereignisse beschreibt der [Komponentenleitfaden](https://boulea7.github.io/swarmloom/docs/en/element.html).

## Installation nach Plattform

Store-Einträge und signierte Pakete sind noch nicht verfügbar. Alle folgenden Methoden verwenden die Entwicklungspakete, die `pnpm build` im vorherigen Schritt erzeugt hat.

<details>
<summary>Chrome / Edge / Brave / Opera</summary>

- Chrome: Öffne `chrome://extensions`, aktiviere den Entwicklermodus, wähle „Entpackte Erweiterung laden“ und dann `apps/extension/dist/chrome/`.
- Edge: Öffne `edge://extensions` und wähle `apps/extension/dist/edge/`.
- Brave / Opera: Aktiviere auf der jeweiligen Erweiterungsseite den Entwicklermodus und wähle ebenfalls `dist/chrome/`.
- Auf einer normalen Webseite klickst du auf das Symbol in der Symbolleiste oder drückst Alt+Shift+W. Auf browserinternen Seiten, in Webstores und im integrierten PDF-Viewer können Erweiterungen nicht ausgeführt werden.

</details>

<details>
<summary>Firefox für Desktop und Android (signierte Veröffentlichung geplant)</summary>

Desktop: Öffne `about:debugging#/runtime/this-firefox`, wähle „Temporäres Add-on laden“ und dann `apps/extension/dist/firefox/manifest.json`; Firefox entfernt es beim Neustart. Android verwendet dasselbe Paket; zum Debuggen benötigst du web-ext, ADB und ein Gerät mit aktiviertem Debugging. Für eine dauerhafte Installation ist die von AMO signierte Veröffentlichung erforderlich; nutze bis dahin Studio auf Smartphones als PWA.

</details>

<details>
<summary>Safari macOS / iOS / iPadOS / visionOS (Gerätetests und Signierung geplant)</summary>

Auf einem Mac mit Xcode führst du `pnpm --filter @swarmloom/extension package:safari` aus, öffnest `apps/extension/build/safari/` in Xcode, wählst dein Team und startest die Container-App. Anschließend aktivierst du die Erweiterung in den Systemeinstellungen. Für die Installation auf einem Gerät ist eine Mitgliedschaft im Apple Developer Program erforderlich; Tests auf realen Geräten mit diesen Systemen stehen noch aus.

</details>

<details>
<summary>PWA: Desktop, Android, iOS / iPadOS</summary>

Öffne Studio in Chrome / Edge und wähle in der Adressleiste oder im Menü „App installieren“. In Safari auf macOS wählst du „Zum Dock hinzufügen“, auf Android „App installieren“ oder „Zum Startbildschirm hinzufügen“; auf iOS / iPadOS wählst du im Teilen-Menü von Safari „Zum Home-Bildschirm“. Verwende Studio in Firefox auf dem Desktop in einem normalen Tab.

</details>

<details>
<summary>Faltbare Geräte und Smartwatches</summary>

Für faltbare Geräte ist nichts zusätzlich erforderlich: Unterstützt der Browser Viewport Segments, teilt Studio die Darstellung in zwei nebeneinander oder übereinander angeordnete Bereiche; andernfalls verwendet es das normale Layout. Für Smartwatches gibt es weder eine Erweiterung noch eine Zusage für eine vollständige PWA. Mit `?watch=1` öffnest du einen kleinen Player, der stummgeschaltet startet; `?round=1` ist für runde Zifferblätter gedacht. Exportiere größere Szenen auf einem anderen Gerät und sieh dir das Ergebnis an.

</details>

## FAQ

1. **Steckt KI hinter den Cursorn?** Nein. Die Cursor sind lokale Animationen, die von einem festen Seed gesteuert werden. Es wird kein Modell aufgerufen, und Skripte in Dokumenten oder HTML werden niemals ausgeführt.
2. **Werden lokale Dateien hochgeladen?** Nein. Dateien werden in deinem Browser verarbeitet. Dein Browser kontaktiert eine Website nur, wenn du deren URL öffnest; in HTML verlinkte Bilder und Schriftarten kannst du in den Studio-Einstellungen deaktivieren. Siehe [Datenschutz](../../PRIVACY.md).
3. **Warum können manche Seiten nicht direkt neu aufgebaut werden?** Browser lassen die Ausführung von Erweiterungen auf internen Seiten, in Webstores und im integrierten PDF-Viewer nicht zu. Ziehe die Datei stattdessen in Studio; bei einer normalen Seite, für die du dich anmelden musst, verwendest du die Erweiterung.
4. **Liefern gleiche Einstellungen eine byteidentische MP4-Datei?** Bild und Ton sind Frame für Frame identisch, sofern Eingabe, Browser, Schriftarten, Betriebssystem und Einstellungen übereinstimmen. Die MP4-Datei selbst kann sich bei unterschiedlichen Encoder-Versionen trotzdem auf Byte-Ebene unterscheiden.
5. **Können Smartphones und Smartwatches die Erweiterung installieren?** Nutze auf Smartphones vorerst Studio als PWA; eine signierte Veröffentlichung für Firefox Android ist geplant. Auf Smartwatches gibt es nur den kleinen Player, keine Erweiterung und keine Hintergrundwiedergabe.
