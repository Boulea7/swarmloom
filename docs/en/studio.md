# Studio

::: warning Current status
Studio's interface and export paths are still being implemented, and the deployment URL is a planned entry point. This page describes v1 behaviour.
:::

Studio is SwarmLoom's browser workbench and an installable PWA. Planned address:

[https://boulea7.github.io/swarmloom/studio/](https://boulea7.github.io/swarmloom/studio/)

It is intended for files, pasted text, public URLs and examples. It does not replace the extension's access to the current tab's DOM.

## Home

The home screen offers four entry points:

- **Drop or open a file** in one of the [supported formats](./formats).
- **Paste** a small Markdown, SVG, HTML or source-code input; Jupyter notebooks, terminal recordings (asciicast) and patches are recognised by their content.
- **URL** to request a remote file or page.
- **Example gallery** with one licence-cleared sample per format, playable on click.

Adapters load on demand. The first use of a format may fetch its module; cached modules can work offline.

Back and Forward in the browser reopen each step's own local file. A tab keeps the last 8 local files; older entries ask you to pick the file again. Changing the interface language does not interrupt what is playing and keeps any URL or pasted text on the home screen that was not opened yet.

## Player

The player uses an inline stage with its own scrolling content. Its settings drawer includes:

- Cursor count, speed and labels;
- Light and dark themes;
- Sound toggle and sound pack;
- `flock`, `halo` and `none` finales;
- Reduced motion;
- Interface language.

Below the stage, the progress bar becomes a time line you can drag when the player can seek. Once the build is playing, drag it anywhere; arrow keys move 2%, Page Up/Down 10%, and Home/End jump to the start or the end. The count beside it shows the layers built.

Phones use a bottom settings sheet. Watch mode omits full settings and keeps only the minimum viewing controls.

## URL parameters

| Parameter | Purpose |
| --- | --- |
| `?example=<id>` | Open a bundled example |
| `?src=<url>` | Open a URL-encoded remote source |
| `#d=<payload>` | Open small text content compressed into the hash |
| `?autoplay=1` | Play after loading; sound still follows browser gesture policy |
| `?watch=1` | Use the small, round-safe viewing layout |
| `?import=1` | Highlight the file picker (links from the extension); keeps the normal home screen even on a watch-sized screen |

`#d=` uses deflate-raw and base64url and should be generated by Studio rather than assembled by hand. A hash is not sent with an ordinary HTTP request, but anyone receiving the link can still read it.

## Offline use

After PWA installation, the Service Worker caches the app shell and, at install, fetches every format's adapter chunks together with what they import. Local files, cached examples and existing scenes can then run offline. The worker's version is a hash of the content of every cached file, so a change to only the page, the manifest or an icon still reaches installed copies.

Offline mode does not make remote URLs readable. First-use formats, uncached remote resources, external fonts and model dependencies still need a network. Clearing site data removes the cache.

## System sharing and file handlers

On supported Chromium platforms, an installed PWA can register through its manifest:

- `share_target` for text, URLs or files from system sharing;
- `file_handlers` as an open-with target for supported extensions.

These are not universal capabilities. iOS and other platforms retain copy, paste, file selection and outbound system sharing as alternatives. Installing the PWA does not give Studio access to another tab's cookies, authenticated state or DOM.

## Remote URL limits

Studio fetches URLs directly in the browser, so same-origin policy, CORS, mixed content and site permissions still apply.

- Public files that allow browser reads can be imported directly.
- Knowing the URL of an authenticated page does not make it readable.
- Studio has no default server proxy and does not ask for your cookies.
- Use the extension in the original tab when you need its authenticated live DOM.
- Use the CLI's local browser workflow for fixed-viewport, unattended capture.

The remote site may log requests. Opening only a local file does not upload its content.

The Studio page carries a Content-Security-Policy that backs up every format's sanitizer: only Studio's own scripts run, and from the web only https images, fonts and the file you open load. Turning off **Load web images and fonts** adds a stricter policy that blocks web images and fonts too; turning it back on needs a page reload, which Studio offers.

## Foldables and small screens

Studio always has an ordinary responsive layout. Supported Chromium environments can add dual-screen enhancements through Viewport Segments:

- Horizontal dual screen: the full stage on one segment and settings on the other.
- Vertical dual screen: stage above, controls below.
- Fold or rotate: recompute presentation without resetting the seed or timeline.

`?watch=1` or a watch-sized screen (up to 320 × 400) uses the tiny player; a narrow window on a bigger screen and `?import=1` links keep the normal Studio. It shows a static poster first, is muted by default, and has a large play button, progress and **Open on phone**. It does not depend on poorly supported round-display media queries.

## Export and sharing

**Export** uses live region capture where supported and creates WebM with synchronised sound. Unsupported browsers show the equivalent `npx swarmloom render ...` command instead of disguising an unreliable canvas redraw as export.

**Share** can put small text into `#d=`. Export a video or share the original file for large content. Check for sensitive material before sharing.

## Studio inside the extension

The extension is planned to bundle the same Studio build for PDF, document, image and model links, and for restricted pages.

Extension mode uses relative assets and does not register a Service Worker. It keeps the same format pipelines and privacy boundaries without contacting a separate SwarmLoom service.
