# Studio

::: info 当前状态
Studio 已经上线，地址见下方；支持 WebCodecs 的浏览器可以直接用“在浏览器里导出”。“用命令行渲染”给出的命令需要 `swarmloom` CLI，它还没有发布到 npm，目前需要从源码构建（见 [CLI](./cli.md)）。本页描述 v1 行为。
:::

Studio 是 SwarmLoom 的浏览器工作台，也是可安装 PWA。地址：

[https://boulea7.github.io/swarmloom/studio/](https://boulea7.github.io/swarmloom/studio/)

它适合文件、粘贴文本、公开 URL 和示例，不替代扩展的当前标签页 DOM 访问能力。

## 首页

首页提供四种入口：

- **拖放或打开文件**：使用[支持的格式](./formats)中的本地文件。
- **粘贴**：输入小型 Markdown、SVG、HTML 或源码；Jupyter 笔记本、终端录制（asciicast）和补丁按内容识别。
- **URL**：请求远程文件或页面。
- **示例墙**：每种格式一个许可清晰的样例，点击卡片即播放。

适配器按需加载。第一次打开某类文件时需要取得对应模块；已经缓存的模块可离线使用。

浏览器的后退和前进会重新打开每一步自己的本地文件。标签页只保留最近 8 个本地文件，更早的记录会提示重新选择文件。切换界面语言不会打断正在播放的内容，也不会清空首页里还没打开的网址和粘贴内容。

## 播放页

播放页使用内联舞台，内容在自己的滚动区域中重建。设置抽屉包含：

- 光标数量、速度和标签；
- 明暗主题；
- 音效开关与音效包；
- `flock`、`halo`、`none` 结尾；
- 减少动态效果；
- 界面语言。

舞台下方的进度条在播放器支持跳转时是一条可拖动的时间轴：开始播放后可拖到任意位置，方向键每次移动 2%，Page Up/Down 移动 10%，Home/End 跳到开头或结尾。右侧显示已完成的图层数。

手机使用底部设置抽屉。手表模式不提供完整设置，只保留观看所需的最少控件。

## URL 参数

| 参数 | 用途 |
| --- | --- |
| `?example=<id>` | 打开内置示例 |
| `?src=<url>` | 打开经过 URL 编码的远程来源 |
| `#d=<payload>` | 打开压缩在 hash 中的小型文本内容 |
| `?autoplay=1` | 加载后自动播放；声音仍受浏览器手势策略限制 |
| `?watch=1` | 使用小屏、圆屏安全的观看布局 |
| `?import=1` | 突出显示文件选择（扩展发来的链接），手表大小的屏幕上也保留普通首页 |

`#d=` 使用 deflate-raw 与 base64url 编码，应由 Studio 生成，不建议手工拼接。hash 不随普通 HTTP 请求发送，但链接本身仍会被接收者看到。

## 离线使用

安装 PWA 后，Service Worker 缓存应用壳，并在安装时预取各格式的适配器分包和浏览器内视频导出模块，以及它们的依赖。离线时可以打开本地文件、播放缓存示例和重建已有内容。Service Worker 的版本按所有缓存文件的内容计算，只改页面、manifest 或图标也会推送给已安装的客户端。

离线不代表远程 URL 可读取。首次使用的格式、未缓存的远程资源、外部字体和模型依赖仍需要网络。清除站点数据会移除缓存。

## 系统分享与文件入口

支持的 Chromium 环境中，已安装 PWA 可通过 manifest 注册：

- `share_target`：接收系统分享的文本、URL 或文件；
- `file_handlers`：作为受支持扩展名的打开方式。

这些能力不是全平台基线。iOS 等环境保留复制、粘贴、文件选择和系统“分享”作为替代。安装 PWA 不会让 Studio 获得其他标签页的 Cookie、登录态或 DOM。

## 远程 URL 的边界

Studio 直接在浏览器请求 URL，因此受同源策略、CORS、混合内容和站点权限约束。

- 公开且允许读取的文件可以直接导入。
- 需要登录的页面不会因为 Studio 知道 URL 就变得可读。
- Studio 默认不提供服务器代理，也不会要求你提交 Cookie。
- 需要当前页面登录态和实时 DOM 时，在该页面使用扩展。
- 需要固定视口和无人值守抓取时，使用 CLI 的本地浏览器流程。

远程站点可能记录请求。仅打开本地文件不会触发内容上传。

Studio 页面带有 Content-Security-Policy，作为各格式清洗步骤的兜底：只运行 Studio 自己的脚本，网络上只允许 https 图片、字体和你打开的文件。关闭“加载网络图片和字体”后会追加更严格的策略，网络图片和字体也会被拦截，在浏览器里导出时也不会请求它们；重新打开该设置需要刷新页面，Studio 会给出提示。

## 折叠屏与小屏

Studio 始终有普通响应式布局。在支持 Viewport Segments 的 Chromium 环境中，再启用双屏增强：

- 左右双屏：一段显示完整舞台，另一段显示设置。
- 上下双屏：舞台在上，控件在下。
- 折叠或旋转：只重算展示布局，不重置种子和播放时间线。

`?watch=1` 或手表大小的屏幕（不超过 320 × 400）使用精简播放器；大屏上的窄窗口和 `?import=1` 链接仍是普通 Studio。精简播放器：静态 poster 先行、默认静音、大播放按钮、进度和“在手机打开”。不依赖尚未广泛支持的圆屏媒体查询。

## 导出与分享

“导出”（快捷键 `E`）在同一个对话框里提供两种出视频的方式。先选尺寸（1280 × 720、1920 × 1080、1080 × 1920 或 1080 × 1080）、30 或 60 fps，以及是否包含声音。

- **在浏览器里导出**：在页面内逐帧渲染视频。一个隐藏的 frame 运行与 `swarmloom render` 相同的渲染页，按整帧推进同一个虚拟时钟，收尾时长也相同，所以同样设置下的画面与 CLI 一致。每一帧从页面快照绘制，用 WebCodecs 编码（MP4 内的 H.264；没有 H.264 时用 WebM 内的 VP9），再由 [Mediabunny](https://github.com/Vanilagy/mediabunny) 封装。声音来自这次播放的声音日志，离线渲染后编码为 AAC 或 Opus；两种都不支持时视频没有声音，对话框会说明。进度条显示帧数和剩余时间，“取消”立即停止，“下载”保存文件。导出期间页面仍可操作，请保持标签页打开。
- **用命令行渲染**：给出生成同一个文件的 `npx swarmloom render ...` 命令，包含所选尺寸、帧率、主题、语言、声音和网络图片设置，以及相同的 10 分钟时长上限（`--max-duration 600`；CLI 自身默认 120 秒），另外还能选 WebM、GIF 和 WebP。

不支持 WebCodecs（没有 `VideoEncoder`）的浏览器只显示命令。导出模块和 Mediabunny 不在 Studio 启动时加载：普通访问时，第一次打开对话框才加载；安装 PWA 时，它们会和各格式的适配器一起提前下载（见上文“离线使用”）。

浏览器内导出的限制：

- 1280 × 720 下每帧约 0.1 到 0.2 秒，35 秒的视频约需 3 分钟。导出期间随时响应输入：每帧的快照每隔几毫秒让出一次主线程，绘制一帧最多占用约十分之一秒。
- 画面来自页面的 SVG 快照，不是截图。自定义的 `::marker` 和 `::first-letter` 样式、`position: sticky`、WebGL canvas，以及不允许 CORS 的跨源图片（留空，对话框会说明有几个）可能与 CLI 不同。
- 使用 Studio 里选的音效包；CLI 总是使用默认音效包。
- 编码器不同：Chromium 把 H.264 标记为 BT.601，CLI 写 BT.709，解码后的颜色可能差几个色阶。Linux 上的 Chromium 没有 AAC 编码器，MP4 里的声音是 Opus，音轨可能比视频长不到 20 毫秒。
- 与 CLI 一样，导出不跟随系统的“减少动态效果”设置和屏幕像素密度：页面和 3D 模型按完整动效构建，每个 CSS 像素对应一个设备像素。页面用 `srcset` 选的图片仍跟随屏幕；在高密度屏幕上，浏览器给文字边缘做的抗锯齿可能略有不同，所以画面可能与 CLI 或在其他屏幕上的导出略有差别。
- 同一输入和种子在同一块屏幕上导出两次，每一帧的像素相同，但浏览器编码器每次写出的字节不完全相同，差别肉眼看不出。

“分享”可把小型文本写进 `#d=`。大型内容请导出视频或分享原始文件。分享前检查内容是否敏感。

## 扩展内置 Studio

发行构建（`pnpm build:extension`）在每个扩展包里内置同一份 Studio 构建，用于打开 PDF、文档、图片、模型链接，以及经提示页打开受限页面。用 `--without-studio` 做的本地构建会改用在线 Studio 打开这些链接。

扩展模式使用相对资源路径，不注册 Service Worker。它仍遵循相同的格式管线和隐私边界，不需要连接独立的 SwarmLoom 服务。
