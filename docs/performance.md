# 性能

::: info 测量状态
本页数字是设计预算。`pnpm bench` 在 demo 页和一个约 4400 图层的合成页上测量快照耗时、帧率、长任务、舞台节点数和堆内存，并按更宽松的回归预算判定；场景与最近一次结果见[性能基准](./benchmarks.md)。这些结果来自一台共享 Linux 机器，不能证明所有设备都达到目标。
:::

## 设计预算

首个版本以中端笔记本为基准环境，目标是在 **48 个光标、约 4000 个图层**时保持 55 fps 以上，单帧脚本预算不超过 6 ms。移动端与大型 3D 场景采用更低的并发和资源预算。

这些目标需要在固定浏览器、字体、视口、DPR、输入样例和构建版本下验证。没有这些条件，单个 FPS 数字没有可比性。

## 引擎如何控制开销

### 单 Canvas 光标层

光标、名字标签、状态气泡、选框和测量线规划绘制在同一个覆盖 canvas 上，而不是每帧更新几十个 DOM 节点。图层内容与临时辅助层分离。

### 视口虚拟化

只挂载视口附近约 1.5 屏范围内的图层。远离视口且没有进行中的图层会卸载，进行中的任务状态仍由引擎保留。

快照默认上限为 6000 图层和 60000 CSS px 世界高度。达到上限时设置 `Blueprint.truncated` 并显示原因，不静默丢内容。

快照遍历按约 10 ms 的时间片执行：遍历期间页面保持响应，`signal` 在一个时间片内生效。两个时间片之间如果页面让已遍历的内容重排（图片或字体加载完成、定时器撑高横幅），遍历会从头再来；连续两次被打断后，最后一次在单个任务里跑完，保证结果只对应一种布局。起点在 `maxHeight` 以下的子树，以及图层数超过约两倍 `maxLayers` 之后的内容，只粗扫其中的 fixed 和绝对定位元素，不读取文字和盒样式，所以长页面的快照耗时主要取决于保留下来的部分，而不是整个 DOM 的大小。

### 读写分批

布局读取与样式写入分批进行，避免在同一循环中交替调用几何读取和 DOM 修改。最终几何在播放前确定，揭示过程优先使用 transform、clip 或绘制进度，不反复重排整篇文档。

### 空间哈希群聚

群聚结尾使用空间哈希查找邻居，避免每个光标都与所有其他光标两两计算。光标数量应有上限，不为更多任务无限增加光标。

### 按需加载

PDF、Office、3D 解码器、数学和图表等依赖只在对应输入出现时加载。播放一个已经生成的 Blueprint 不需要再次运行原始编译器。

## 大输入建议

- 优先导入 PDF 来保持固定文档版式，而不是反复尝试复杂 DOCX 排版。
- 超长 Markdown 和源码按章节或文件拆分；需要完整长页时保留截断提示。
- 大表格减少逐字单元格，使用分块填充；不要给每个单元格一个任务。
- 位图先缩放到实际展示需求，避免解码远超输出尺寸的图片。
- 3D 优先使用单文件 GLB，压缩纹理并使用固定 LOD；不要把每个三角面做成 DOM 图层。
- 远程资源在播放前完成解码，避免网络完成顺序改变布局和导出结果。

## 交互卡顿时的调整

1. 把 `agents` 从较高固定值改为 `auto`，或手动降低数量。
2. 保留 `reducedMotion: "auto"`；不需要结尾时设置 `finale: "none"`。
3. 关闭不需要的标签和工具栏动画，减少遮挡区域。
4. 降低输出视口与 `--scale`。2× DPR 会产生约四倍像素。
5. 检查输入是否包含超大图片、复杂阴影、滤镜、视频或高面数模型。
6. 关闭其他高负载标签页，再使用浏览器 Performance 面板定位长任务。

提高 `speed` 会缩短时长，不一定降低每帧成本。它不能代替降低场景复杂度。

## 后台标签页与暂停

`RealtimeClock` 默认把单次 tick 的最大间隔限制为 100 ms。后台标签页降频或调试器暂停后，不会让引擎突然跳过整个构建。

`pause()` 停止引擎推进。恢复时从相同状态继续，不补算暂停期间的墙钟时间。

## 确定性导出的性能原则

导出模式不根据瞬时 FPS 自动改变 LOD、光标数或揭示顺序。每次固定推进 `1000 / fps` 毫秒，等待 `player.ready()` 后捕获。

这意味着慢机器上的导出可能耗时更长，但不应因此得到不同画面。编码速度也不应改变引擎时间线。

## 如何报告性能问题

一个可比较的性能报告应包含：

- SwarmLoom、浏览器和操作系统版本；
- CPU、内存、GPU 与设备类型；
- 视口宽度、高度和 DPR；
- 光标数、图层数、输入格式与最小样例；
- 是否启用声音、光环、3D 和减少动态；
- Performance trace、长任务和内存峰值；
- 预期与实际结果。

不要上传含隐私内容的原始文档或完整 profile。先制作最小、脱敏的复现样例。

## 基准命令

```bash
pnpm bench
```

它在无头 Chromium 中运行各基准场景，任一回归预算不满足时以退出码 1 结束。请在空闲机器上单独运行；参数、预算和最近一次结果见[性能基准](./benchmarks.md)。
