# @swarmloom/adapter-docx

The DOCX adapter for SwarmLoom. It turns a Word document (.docx) into page sheets on a desk and snapshots them into a blueprint. Each page becomes a `page` box layer, and the page's text, pictures and tables are layers inside it. It runs in the browser and needs no server or Office install. Load it through `@swarmloom/formats` so that it, docx-preview and JSZip are only fetched when a .docx is opened.

```ts
import { loadDocx } from "@swarmloom/adapter-docx";

const { blueprint, notes, pages, renderer } = await loadDocx({ name: "report.docx", bytes }, { document, width: 1000, theme: "light" });
```

## Pipeline

1. **Checks.** The file must be at most 100 MB (`maxBytes`). The ZIP package may hold at most 10,000 entries and 512 MiB unpacked, with a compression ratio of at most 200:1. ZIP64, encrypted entries and unsafe entry names are rejected. Every XML part is checked before it is parsed: DTD and entity declarations are refused and nesting is capped at 256 levels. Password-protected files and Word 97-2003 files renamed to .docx are recognised and reported.
2. **Rendering.** docx-preview renders the document into a closed sandbox, with pictures as data URLs. Comments, tracked changes and embedded alternative-format chunks are not rendered. Before rendering, the parsed model is corrected in three places:
   - sheets start at sections and page breaks (see Pagination);
   - a footnote reference in a superscript run is rendered once;
   - sections without their own header or footer inherit the previous section's, as in Word.
3. **Clean-up.** Scripts, frames, embeds, forms, event handlers and `@import` are removed. Links keep http(s), mailto and in-document targets; pictures keep data and blob URLs only, so nothing is fetched from the network. Fonts that are not installed get metric-compatible fallbacks from the shared table in `@swarmloom/core` (`FONT_FALLBACKS`, decisions F01: Calibri to Carlito, Cambria to Caladea, SimSun to Noto Serif SC, and so on). List numbers and bullets become real text. Heading paragraphs get the ARIA heading role, so snapshots classify them as headings.
4. **Snapshot.** Sheets wider than the screen are narrowed: margins shrink and text reflows, nothing is scaled. The sheets are then measured and snapshotted with snapshot-dom, and the content is grouped under its page layers.

If docx-preview fails on a document, a built-in plain renderer takes over (`renderer: "auto"`, the default). It keeps headings, paragraphs, lists, tables, hyperlinks and page breaks, leaves out pictures, headers, footers and footnotes, and says so in `notes`. Use `renderer: "preview"` to fail with `render-failed` instead, or `"plain"` to use only the built-in renderer.

## Pagination

Word's automatic page flow is not imitated. A new sheet starts only at:

- a section that starts on a new page;
- an explicit page break, or a paragraph with "page break before";
- a page break Word saved when the file was last laid out (`w:lastRenderedPageBreak`). Turn this off with `savedPageBreaks: false`.

Content between two breaks stays on one sheet, which grows as needed. When a sheet runs well past its page height, `notes` says that pages can be longer than in Word.

## Notes and errors

`loadDocx` returns a `DocxLoadedSource`:

- `notes` holds short English sentences for the UI: the fallback renderer, font substitutes and pagination. It is a field of `DocxLoadedSource`; the core `LoadedSource` contract does not define it.
- `pages` is the number of sheets.
- `renderer` is the renderer that produced them.

Failures throw a `DocxError` with a stable `code`: `not-docx`, `encrypted`, `legacy-doc`, `too-large`, `corrupt`, `unsafe` or `render-failed`.

`@swarmloom/adapter-docx/paged` exports the shared page-sheet helpers: sandbox, desk theme, sanitizer, font fallbacks, list markers, page grouping and snapshot. `@swarmloom/adapter-doc` uses them.
